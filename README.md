# archmap

**Architecture Mapper** — one knowledge graph for your codebase.

> If I change this piece of code, what else could be affected, and why?

A single npm package that maintains one knowledge graph of a repository and answers impact/dependency questions. Works on any repo across languages.

## Install

```bash
npm install -g archmap
# or
npx archmap <command>
```

## Quick Start

```bash
# Index the repo into one graph
archmap init .

# Non-coder / overview
archmap guide              # walkthrough
archmap summary            # what is in this codebase
archmap insights           # cycles, coupling, hotspots
archmap ui                 # visual map (overview first, not a file hairball)

# Coder / change-safety
archmap explain <name>     # what this is, who uses it
archmap impact <name>      # what else could break, and why
archmap tests <name>       # which tests to run
archmap plan_change <name> # files you are allowed to edit
archmap trace A B          # evidence-backed why-path
```

Every command supports `--json` for agents and CI.

## Commands

| Command | Description |
|---------|-------------|
| `archmap init [path]` | Create `.archmap/`, index repo, write `.gitignore` + `.mcp.json` |
| `archmap sync [path]` | Re-index on demand |
| `archmap impact <id>` | Bounded blast radius + why-paths |
| `archmap diff [base] [head]` | Symbol-level diff impact |
| `archmap flow <id>` | Reconstruct evidence-backed flow |
| `archmap graph` | Export graph view (json\|mermaid) |
| `archmap search <q>` | RAG + graph search |
| `archmap symbol <id>` | Node + neighbors summary |
| `archmap neighbors <id>` | Adjacent edges/nodes |
| `archmap why_path <from> <to>` | Evidence-backed paths |
| `archmap tests_to_run <id>` | Tests + inferred command |
| `archmap docs <name>` | Resolve documentation |
| `archmap pin --from --to --type` | Add user-confirmed edge |
| `archmap health` | Graph consistency + inference health |
| `archmap insights` | Cycles, coupling, bottlenecks, hubs, isolated modules, hotspots |
| `archmap docs <name>` | In-repo README / ADR / docs for a component |
| `archmap plan_change <id>` | Bounded mutation envelope |
| `archmap ui` | Localhost visualizer (Overview / Code / Insights) |
| `archmap mcp` | MCP server over stdio |
| `archmap serve` | Optional HTTP daemon |

Every command supports `--json` for machine-readable output.

## Architecture

```
archmap/
├── src/
│   ├── core/           # THE Core — contracts, store, impact, policies
│   │   ├── types.ts    # Canonical node/edge types, envelope
│   │   ├── ids.ts      # Stable ID generation (fn:, api:, table:)
│   │   ├── store.ts    # SQLite graph store (node:sqlite)
│   │   ├── impact.ts   # Blast radius + why-paths
│   │   ├── diff.ts     # Symbol-level diff impact
│   │   ├── policy.ts   # Architecture policy evaluation
│   │   ├── rag.ts      # Lexical search over graph
│   │   ├── journal.ts  # Append-only event log
│   │   ├── health.ts   # Graph consistency checks
│   │   └── flow.ts     # Flow reconstruction
│   ├── parse/          # Layered parser (tree-sitter baseline)
│   ├── cli/            # CLI over Core operations
│   ├── mcp/            # MCP server (stdio)
│   ├── daemon/         # HTTP server
│   └── ui/             # Localhost visualizer
└── test/               # Core-first tests
```

### Core Design Principles

- **One graph of truth.** One SQLite database, one set of nodes and edges.
- **Evidence-backed edges.** Every edge has file, line, and snippet evidence.
- **Stable IDs.** `fn:src/app.ts:main`, `api:POST:/items`, `table:users`.
- **Deterministic.** Works fully with zero AI. LLM features are opt-in.
- **Any language.** Regex-based extraction works everywhere; tree-sitter is the upgrade path.

### Node Kinds

`Repo` `File` `Module` `Package` `Class` `Interface` `Function` `Method` `Service` `API` `Route` `Table` `Column` `Event` `Job` `Test` `External` `Infra` `Doc` `Contract` `ConfigKey`

### Edge Kinds

`CONTAINS` `IMPORTS` `CALLS` `IMPLEMENTS` `EXPOSES` `CONSUMES` `READS` `WRITES` `PUBLISHES` `SUBSCRIBES` `TESTS` `DEPENDS_ON` `DOCUMENTS` `CONSTRAINED_BY` `CO_CHANGED` `BROKE_BEFORE` `USES_CONFIG`

## Workspace Files

Generated by `archmap init`:

```
.archmap/index.db      # SQLite graph database
.archmap/seed.yaml     # Optional user corrections
.archmap/journal.jsonl  # Append-only event log
.mcp.json              # MCP server config for editors
```

## MCP Integration

`.mcp.json` is auto-generated for editor integration:

```json
{
  "mcpServers": {
    "architecture-mapper": {
      "command": "npx",
      "args": ["-y", "archmap", "mcp"],
      "cwd": "${workspaceFolder}"
    }
  }
}
```
